# worldpopulation Architecture

Reference documentation for module structure, implementation details, and maintenance guides. See CLAUDE.md for behavioral rules.

## Module Architecture

**data_download.R** - External data management
- Downloads GHS-POP from EC JRC servers
- Caches to user directory (not package directory - CRAN requirement)
- Handles multiple years (1975-2030) and resolutions (100m, 1km, 3ss, 30ss)
- Key function: `load_ghspop_raster()` (internal) loads and caches in memory

**population_analysis.R** - Core spatial operations
- `population_in_circle()` - Atomic operation (lat/lon/radius → population)
- `population_in_circles()` - Vectorized multi-radius (more efficient)
- `population_in_rings()` - Annular rings via subtraction
- All functions create sf buffers, then use `exactextractr::exact_extract()` with `fun = "sum"`

**batch_analysis.R** - Multi-city processing
- `rank_cities_by_population()` - Main use case (rank cities at one radius)
- `compare_cities()` - Multi-city, multi-radius profiles
- `top_cities_in_region()` - Bounding box filtering + ranking
- Creates all buffers at once, extracts in single `exact_extract()` call for efficiency

**city_data.R** - Built-in city dataset
- Provides `load_world_cities()` for 1,000 major cities
- Filter functions by country, population, top N
- Dataset generated by `data-raw/cities.R` and saved to `data/world_cities.rda`

**city_data_download.R** - City data source downloaders (internal)
- `download_simplemaps()`, `download_geonames()`, `download_naturalearth()`
- Used by `data-raw/cities.R` to generate the world_cities dataset
- Not exported (internal functions only)

**utilities.R** - Validation and helpers
- `validate_coordinates()`, `check_radius()`, `validate_year()`
- `get_cache_dir()`, `cache_info()`, `clear_cache()` - Data directory management

**globals.R** - Package environment (`.pkg_env` caches loaded rasters)

## Implementation Details

### Why exactextractr over terra::extract()?
Standard extraction treats each pixel as a point. If a circle covers 30% of a pixel, you get 0% or 100% of its population. `exactextractr` calculates exact coverage (30% → 30% of pixel population):
- **Higher accuracy** for small radii
- **7x faster** performance (8-9ms vs 56-62ms)

### Package Environment Caching
```r
.pkg_env <- new.env(parent = emptyenv())  # In globals.R
# In load_ghspop_raster(): cache_key → check → load → assign
```
Avoids reloading the same raster multiple times — critical for batch operations.

### Batch Processing
```r
# BAD: Loop (N separate extractions)
for (i in 1:nrow(cities)) pop[i] <- population_in_circle(...)

# GOOD: Vectorized (single extraction)
results <- rank_cities_by_population(cities, radius_km)
```
Single `exact_extract()` call for all geometries → 50x faster for 200 cities.

### URL Construction for GHS-POP
- Base: `https://jeodpp.jrc.ec.europa.eu/ftp/jrc-opendata/GHSL/GHS_POP_GLOBE_R2023A`
- URLs may change with new releases — check https://ghsl.jrc.ec.europa.eu/download.php

### Comparison to Tom Forth's Circle Populations
Tom Forth: GDAL → XYZ → SQLite → C# API on Azure (~1 min response, point-based).
This package: terra → exactextractr, local R, exact pixel coverage, ~8ms/query, no radius limits.

## Maintenance Guides

### Adding New Functions
1. Add to appropriate R/ file with full roxygen2 docs (`@export`, `@param`, `@return`, `@examples`)
2. Add input validation using existing `validate_*()` functions
3. `devtools::document()` to update NAMESPACE
4. Add tests to `tests/testthat/test-{module}.R`

### Adding New City Datasets
1. Edit `data-raw/cities.R`
2. Ensure columns: `city`, `lat`, `lon`, `country`, `iso2`, `iso3`, `population`, `admin_name`
3. Run `source("data-raw/cities.R")` → regenerates `data/world_cities.rda`

### Adding New GHS-POP Years
1. Add year to `list_available_years()` in `data_download.R`
2. Update URL construction if release name changes (e.g., R2023A → R2025A)
3. Update `validate_year()` in `utilities.R`

### Analysis Scripts (`analysis/`)
Example scripts, excluded from package build. Can use ggplot2/dplyr without adding to Imports.
